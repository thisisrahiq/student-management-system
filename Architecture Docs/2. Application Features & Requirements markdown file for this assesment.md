# 2. Application Features & Requirements

## 1. Project Overview

### Application Name

**Student Management System — Registry Module**

### Purpose

Build a focused Registry application for managing the four core workflows required by the technical assessment:

1. Student Enrolment
2. Fees & Payments
3. Assessment Submission
4. Marksheet & Results

### Target Users

- Registry Staff / Staff
- Students

### Required Technology

- Next.js 14+ with App Router
- React.js through Next.js
- PostgreSQL
- Prisma ORM
- Tailwind CSS
- DaisyUI
- Real database persistence

---

# 2. User Roles

## 2.1 Staff

Staff users manage Registry operations.

### Staff Capabilities

- View Registry dashboard.
- Create students.
- Edit/manage student records.
- Search students.
- Filter students.
- View student financial information.
- Assign/manage student fees.
- Record payments.
- View outstanding balances.
- Identify overdue balances.
- Create assessments.
- View submissions.
- Identify late submissions.
- Enter grades.
- Publish results.
- Withhold results.

---

## 2.2 Student

Students interact with their own Registry information.

### Student Capabilities

- View profile information.
- View enrolment information.
- View fees and payment information.
- View available assessments.
- Submit PDF/DOCX files.
- Resubmit work before the deadline.
- View submission status.
- View published results.
- View marksheet after publication.

### Result Visibility Rule

```text
Result Created
      ↓
Withheld
      ↓
Student Cannot See Result
      ↓
Staff Publishes Result
      ↓
Student Can See Result
```

# 4. Fees & Payments Module

## 4.1 Programme Fees

### Payment Requirements

- View total amount paid.

---

## 4.3 Outstanding Balance

Calculate:

```text
Outstanding Balance
=
Assigned Fee
-
Total Payments
```

The displayed balance must update when a payment is recorded.

### Example

```text
Programme Fee:       £10,000
Total Paid:           £6,500
Outstanding Balance:  £3,500
```

## 5.3 Student Submission

Students can:

- View open assessments.
- Upload work.
- Submit PDF files.
- Submit DOCX files.
- View submission status.

---

## 5.4 Submission Rules

### Rule 1 — One Submission

A student can have one active submission per assessment.

### Rule 2 — Resubmission

Resubmission is allowed before the deadline.

### Rule 3 — Late Submission

Late submissions are accepted.

### Rule 4 — Late Flag

Late submissions must be visually identified.

### Example

```text
Submitted: 15 Aug 2026 10:30
Deadline:  15 Aug 2026 23:59

Status: On Time
```

```text
Submitted: 16 Aug 2026 09:20
Deadline:  15 Aug 2026 23:59

Status: Late
```

---

## 5.5 File Requirements

Allowed file types:

- PDF
- DOCX

The application should validate the uploaded file type before accepting the submission.

# 6. Marksheet & Results Module

## 6.1 Grade Entry

Staff can enter a numeric grade for each student per assessment.

### Grade Range

```text
0–100
```

Grades outside this range must not be accepted.

---

## 6.2 Classification

Classification should be automatically determined.

| Grade | Classification |
|---:|---|
| 70–100 | Distinction |
| 60–69 | Merit |
| 40–59 | Pass |
| 0–39 | Fail |

## 6.3 Result Publication

Each result must have a publication state.

### States

```text

Published
```

### Staff

Staff can:

- Enter grade.
- Review grade.
- Publish result.
- Withhold result.

### Student

Students:

- Cannot see withheld results.
- Can see published results.

---

## 6.4 Student Marksheet

The student marksheet should show published results.

Recommended information:

- Assessment
- Module
- Grade
- Classification
- Publication status

Only published results should appear to the student.

# 10. Validation Requirements

## Student Validation

- Full name is required.
- Email is required.
- Email must have a valid format.
- Date of birth is required.
- Programme is required.
- Academic year is required.
- Enrolment status must be one of the allowed values.

## Payment Validation

- Amount is required.
- Amount must be positive.
- Payment date is required.
- Reference number is required.
- Payment must not create an invalid financial state.

## Assessment Validation

- Title is required.
- Module is required.
- Deadline is required.
- Deadline must be a valid date/time.

## Submission Validation

- Student is required.
- Assessment is required.
- File is required.
- File must be PDF or DOCX.
- Submission rules must be enforced.

## Grade Validation

- Grade is required.
- Grade must be numeric.
- Grade must be between 0 and 100.

# 11. Business Rules

## Student ID

```text
Every student must have exactly one unique Student ID.
```

## Enrolment Status

```text
Student status ∈
{Enrolled, Deferred, Withdrawn, Completed}
```

## Payment Balance

```text
Outstanding =
Assigned Fee - Total Payments
```

## Assessment Submission

```text
One student
+
One assessment
=
One submission record

Resubmission is allowed before deadline.
```

## Late Submission

```text
Submission Time > Deadline
        ↓
Accept Submission
        ↓
Mark as Late
```

## Grade Classification

```text
Grade >= 70 → Distinction
Grade >= 60 → Merit
Grade >= 40 → Pass
Grade < 40  → Fail
```

## Result Visibility

```text
Published = false
        ↓
Hidden from student

Published = true
        ↓
Visible to student
```

# 12. Important Edge Cases

The application should account for:

### Students

- Duplicate email.
- Duplicate Student ID.
- Missing required fields.
- Invalid email.
- Invalid academic year.
- Invalid enrolment status.

### Payments

- Zero payment.
- Negative payment.
- Payment greater than outstanding balance.
- Duplicate payment reference.
- No payments.
- Partial payment.
- Fully paid student.
- Overdue balance.

### Assessments

- Missing assessment title.
- Missing module.
- Missing deadline.
- Assessment deadline has passed.
- Submission exactly at deadline.
- Submission after deadline.
- Multiple submissions.
- Resubmission before deadline.
- Resubmission after deadline.
- Invalid file type.

### Results

- Grade below 0.
- Grade above 100.
- Grade exactly 40.
- Grade exactly 60.
- Grade exactly 70.
- Withheld result.
- Published result.
