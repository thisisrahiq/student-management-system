# 3. User Roles & Permissions

## 3.1 Overview

The Student Management System — Registry Module serves two distinct primary stakeholders: **Registry Staff (Administrators)** and **Students**. Although explicit authentication (OAuth, JWT, session cookies) is optional for this technical assessment, **Role Separation** is a core operational requirement. The system implements role-scoped navigation, visibility rules, and workflow capabilities to mirror real-world academic registry governance.

## 3.3 Staff Role Specifications

### Purpose & Scope
Registry Administrators are responsible for maintaining academic integrity, student lifecycle records, financial accounting accuracy, and official grade publishing.

### Key Permissions & Responsibilities
1. **Student Record Governance**:
   - Create new student records with unique auto-generated IDs (`SMS-2025-XXXX`).
   - Update student statuses (`Enrolled`, `Deferred`, `Withdrawn`, `Completed`).
   - Modify contact details, academic year, and programme allocation.
2. **Financial Management**:
   - Associate programme-based tuition fees.
   - Record payment payments with transaction references and dates.
   - Audit outstanding balances and track overdue accounts on the dashboard.
3. **Assessment Operations**:
   - Define module assessments with submission deadlines.
   - Monitor submission counts, file attachments, and on-time vs. late flags.
4. **Marksheet & Result Governance**:
   - Enter student grades (strictly bounded `0–100`).
   - Audit automated classifications (`Distinction`, `Merit`, `Pass`, `Fail`).
   - Toggle publication state (`Withheld` ↔ `Published`) on a per-student or batch basis.

---

## 3.4 Student Role Specifications

### Purpose & Scope
Students access a personalized portal to view their enrolment status, financial balance, assessment deadlines, upload assessment deliverables, and access official results once published.

### Key Permissions & Responsibilities
1. **Personal Profile View**:
   - Inspect official enrolment state, Student ID, email, and academic details.
2. **Financial Statement Access**:
   - View assigned tuition fee breakdown, recorded payment history, and real-time outstanding balance.
3. **Assessment Deliverables**:
   - View active module assessments and submission deadlines.
   - Upload PDF or DOCX format files.
   - Replace/resubmit files prior to deadline expiration.
   - Submit past deadline with automatic `Late` audit flagging.
4. **Academic Results**:
   - Access published marksheet cards containing grade numeric scores and earned classifications.
   - **Confidentiality Enforcement**: Withheld results remain completely invisible in student responses and UI views.

## 3.5 Result Visibility & Confidentiality Rule

A critical business rule is the strict isolation of unreleased academic marks.

```text
                     +-----------------------+
                     | Staff Enters Grade    |
                     | (0-100 & Classifying) |
                     +-----------+-----------+
                                 |
                                 v
                     +-----------------------+
                     | Result State:         |
                     | WITHHELD (default)    |
                     +-----------+-----------+
                                 |
                 +---------------+---------------+
                 |                               |
                 v                               v
    +-------------------------+     +-------------------------+
    | Staff Perspective       |     | Student Perspective     |
    | - Grade Visible (e.g 82)|     | - Result Hidden         |
    | - Action: Publish / Edit|     | - Status: "Pending"     |
    +------------+------------+     +-------------------------+
                 |
                 | Staff Clicks "Publish"
                 v
    +-------------------------+
    | Result State: PUBLISHED |
    +------------+------------+
                 |
                 v
    +--------------------------------------------------+
    | Student Perspective                              |
    | - Grade Visible (82/100)                         |
    | - Classification Visible (Distinction)           |
    | - Downloadable/Printable Marksheet Accessible   |
    +--------------------------------------------------+
```

## 3.6 Role Toggle & Demo Context

To facilitate technical assessment evaluation without requiring complex authentication workflows:
- A global **Role Selector** switch (`[ Switch to Staff View ]` ↔ `[ Switch to Student View ]`) is positioned in the application top navbar.
- In **Student View**, an active student dropdown switcher allows the evaluator to test the application experience from the perspective of different seeded students (e.g. fully paid student vs. overdue student, student with published results vs. withheld results).
